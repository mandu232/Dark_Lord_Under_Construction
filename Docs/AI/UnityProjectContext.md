Updated 2026-09-20. Confirmed from ProjectSettings, Packages, SampleScene, and first-party assets.

- Unity 6000.6.2f1, PC single-player, 2D top-down. URP 17.6 with Renderer2D is selected through QualitySettings (GraphicsSettings fallback is empty).

- Art convention: 16 pixels per unit; one 16x16 tile occupies one world unit. Existing witch sprites already use 16 PPU and Point filtering.
- Main/build scene: Assets/Scenes/SampleScene.unity. It originally contained Player, Main Camera, Global Light 2D. No prior gameplay code or architecture documentation existed.
- Runtime code: Assets/Scripts, assembly DarkLord.Runtime. Small MonoBehaviour components own movement, health, animation presentation, and minion decisions. Editor-only setup and validation are under Assets/Editor. PlayMode tests have their own assembly.
- As of 2026-09-20 SampleScene starts without minions. Player MinionSummoning opens an IMGUI popup with V, creates a worker (max 1) or guards (max 4) on nearby unoccupied connected floor, and registers them with DungeonExpansion/MinionCommands. SummonWorker/SummonGuard prefabs preserve the previous scene units. Summoning is currently free; modal input blocks player controls without pausing the world. See Docs/MinionSummoning.md.
- No networking or persistence is implemented. As of 2026-09-19 SampleScene has DungeonGrid + player DungeonExpansion: a 41x31 sprite-free mesh grid, initial room/corridor and solid rock/bedrock. B/left-click now queues/cancels mining for the single WorkerMiner; it follows cardinal floor BFS paths and mines each rock for 2 seconds. Jobs retain progress on interruption and unreachable jobs wait for a newly opened path. DungeonLayout owns cell state; Unity Grid owns coordinates; future Tilemap rendering can subscribe to CellChanged. DungeonTerrain is assigned to existing combat minion obstacle masks; combat-minion routing is still direct steering. See Docs/DungeonExpansion.md.
- As of 2026-09-20 the Player owns CurrencyWallet (Gold, Souls, Dark Crystals) and SampleScene contains a responsive uGUI/TextMeshPro Game HUD. It shows resource balances, player health, worker/guard counts, and control hints. Tools > Dark Lord > Setup Basic Game UI rebuilds this hierarchy idempotently.
- As of 2026-09-23 SampleScene owns an endless WaveDirector. After a short preparation countdown, invaders spawn from DungeonLayout.Entrance, advance toward the dungeon lord/core, and scale in count and health each wave. Clearing a wave awards Souls and starts the next countdown; player death stops progression. WaveHud shows the countdown, wave number, and remaining invaders. Tools > Dark Lord > Setup Wave System repairs the scene wiring.
- As of 2026-09-22 MainMenu.unity is the separate title/startup scene (build index 0); it loads SampleScene for a fresh dungeon. Editor Play runs the currently open scene without a forced startup override. SampleScene contains only pause/settings/confirmation UI; Esc pauses. Returning to MainMenu requires confirmation and ends the unsaved session. GameMenu restores time/audio/HUD/cursor on resume/unload. GameSettings persists master volume, fullscreen, quality and vSync only after Apply & Save. All menu/HUD TMP text uses supplied Stardust Regular/Bold/ExtraBold with Korean fallbacks; existing summon/mining IMGUI uses the Stardust GUISkin. See Docs/MainMenu.md.
- Unity Pipeline 0.7.0-exp.1 is installed. The existing enabled Codex `unity` MCP entry launches Unity CLI (`unity mcp`). On 2026-09-17 a real stdio MCP handshake discovered 151 tools; editor_status, console_status, and get_scene_hierarchy succeeded against this project (Unity 6000.6.0f1, SampleScene, zero console errors/warnings). Restricted shell discovery can fail; use an approved elevated command for local connection checks, without weakening sandbox settings. Explicitly target this project with `--project-path` for CLI/MCP calls. Never rewrite scene/prefab YAML behind the running editor.
