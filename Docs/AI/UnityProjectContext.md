# Unity project context

Updated 2026-10-06. See Docs/ProjectStructure.md for asset ownership and Docs/AssetMigration.md for previous paths.

- Unity 6000.6.2f1, PC single-player 2D top-down, URP Renderer2D, Input System 1.20. No multiplayer. Three-slot gameplay persistence is described in Docs/SaveGames.md.
- Build scenes: Assets/Scenes/MainMenu.unity and Assets/Scenes/SampleScene.unity. Editor Play uses the open scene. GameMenu loads these paths; pause/settings reuse Assets/Prefabs/UI/SettingsPanel.prefab. Settings persist only on Apply & Save.
- Assets are organized into Art, Animations, Prefabs, Data, Materials. Scripts have DarkLord.Runtime assembly; Editor setup tools and PlayMode tests remain separate. Do not regenerate scene UI or authored animation assets merely to repair references.
- Player uses Assets/Animations/Player/PlayerDirectional.controller. Original Legacy Red actions are in Animations/Player/Source; textures in Art/Characters/Player/LegacyRed. Float Speed/FacingX/FacingY control movement. Preserve animator state and parameter names.
- Sprites use 16 PPU; dungeon tiles are 32px (2 world units). URP PixelPerfectCamera reference resolution is 320x180. Sprite file names and frame names are descriptive PascalCase; GUIDs, file IDs, slicing rectangles, pivots and PPU were preserved during organization.
- BloodSlimeGuard is the active summon prefab in Prefabs/Minions; WaveInvader is in Prefabs/Enemies. MinionController handles local combat, defence posts and invader routes. Death disables collision, unregisters defence and destroys the corpse after 1.5 seconds.
- DungeonLayout owns rock/floor/bedrock, core and a removable entrance. DungeonConstruction reserves 5x5/7x7 rooms and 5x3/3x5 corridors. DungeonGrid opens tiles in sequence, then spawns the selected Prefabs/Dungeon design once. Data/Construction contains BuildItemDefinition; icons are Art/UI/Construction; meshes Art/Dungeon/Meshes.
- B opens bottom ConstructionPanel with Rooms, Minions, Traps, Entrances and Demolition. Square cards show separate right-side details. Room/corridor selection hides windows and doubles the pixel camera reference resolution for wider placement. Right-click cancels selection and restores menu/camera; completed/queued builds remain. Closing, pausing, disabling restores zoom. WASD works during construction.
- Summoning is free, max four guards within three cardinal tiles of player on connected empty floor. GuardPostAt reserves a living guard's original post even during combat; death/removal releases it. Q rally, mass right-click movement, workers and minion status HUD are removed. E returns guards to posts.
- Demolition removes friendly minions, traps and entrance, without death rewards or removing floor/core/enemies. SpikeTrap damages invaders only. Entrance is a single movable spawn point on completed connected floor.
- InvaderDungeonRoute traverses completed sections and clears all living guards in each room before advancing. Guards remain in their assigned room. Core is a separate 300HP objective. Destroying core/player ends waves.
- WaveDirector has no automatic preparation countdown. WaveHud lower-right start button begins each wave only while preparing, unpaused and with an entrance. Removing entrance suspends pending spawns; restoring resumes the same wave.
- Fonts remain in Assets/Font. TMP dynamic font assets can legitimately change during tests. Do not restore their YAML behind the running Editor, which can leave stale glyph/texture references.
- Unity Pipeline MCP is connected to this project. Use AssetDatabase/SerializedObject/PrefabUtility for asset and scene changes; never edit serialized Unity YAML behind the Editor. Preserve .meta GUIDs.
- Editor Setup tools are initial setup/repair utilities, not the routine art workflow. Legacy worker prefab is retained in Assets/Legacy/Prefabs; worker code remains for historical tests and is not used in gameplay.
- Validation: Tools > Dark Lord > Run Gameplay Tests writes Logs/GameplayTests.xml. A prior interrupted test run left stale Pipeline/Test Framework state; cancel inactive pending requests and reload scripts only when no test is active. Never compile or force-stop Play during a test run. Tests must treat destroyed minion references as null.

Organization validation: 162 asset GUIDs and 1,647 sprite local IDs/rects/pivots/PPU preserved. 12 prefabs and 414 object-reference animation keyframes have no missing references. All 80 PlayMode tests passed after path/name updates.

2026-10-06 corridor update: Rooms tab contains two rooms and one ConstructionKind.Corridor card. DungeonSection.Cells is the actual footprint; queue/completion/ownership use Cells rather than bounding rectangles. CorridorTileDesign is a centered 1x1 tile prefab spawned per newly opened cell only after completion. Fixed H/V kinds remain for initial/legacy data. Right-click cancels uncommitted drag and restores menu/zoom. All 83 PlayMode tests passed.

2026-10-06 room spacing: DungeonConstruction.CanPlan expands a room footprint by one tile and rejects overlap with any room section, including the initial core and pending rooms. Both edge/corner contact are rejected; exactly one intervening tile is allowed. Corridor connection requirements remain. TooCloseToRoom is appended to ConstructionResult and shown in placement feedback. Room/LargeRoom descriptions mention the rule.
