# Dungeon core art, relocation and soft floor lighting

Implemented 2026-10-31.

- Facility floor lights now have a 4.4 × 2.2 world-unit footprint (previously 2.8 × 1.4), strength 0.13 (previously 0.28), and a continuous smoothstep radial falloff. Only the light is smoothed; sprite art remains point-filtered. All existing facility prefabs and the core visual use the shared light material.
- New core art: `Assets/Sprite/Dungeon/Facilities/DungeonCore.png`, exactly 32 × 32, 10 RGBA entries including transparency, using the existing shared 12-entry palette. It depicts a crimson heart crystal in a front-facing horned iron/stone shrine, with bronze accents. Generated with the built-in image generation tool, then exported with the existing palette-limited pipeline. Prompt: one strict front-facing, nearly symmetric gothic dungeon-core shrine; heart-shaped crimson crystal, low stone pedestal, restrained bronze trim and flanking spires; horizontal/vertical edges, exact logical 32 × 32 grid and 2px transparent margin, chunky clusters and dark outline, upper-left highlights; no angled sides, text, ground, baked glow/shadow, gradients or antialiasing; only the existing 11 opaque palette colors plus transparency.
- `Assets/Resources/DungeonCoreVisual.prefab` is attached to the existing core ActorHealth by `DungeonGrid.BindCore` during `WaveDirector.Start`. It includes the authored sprite, crimson emission, the shared floor light and projected shadow. Core health and the enemy objective object are preserved.
- Usage: during preparation, open the core with F and click **코어 이동** in the lower-left of its technology window. Choose a connected, completed room's empty floor with the left mouse button. Right-click or Esc cancels. Movement is blocked during invasions, pauses, the active tutorial, and on occupied cells, corridors, entrances or alchemy stations. There is no item/resource cost.
- The original `DungeonLayout.Core` stays the initial map/construction origin. The new `ActiveCore` / `DungeonGrid.CoreCell` tracks the movable objective. Reservations, minion landing/patrol exclusions, entrance connectivity, merchant arrival location and invader room selection use its active position. Existing map geometry is not rebuilt on relocation.
- Optional `DungeonSaveData.hasCoreCell` / `coreCell` records preserve the position without changing save version 1. Legacy records fall back to the original core location. Saved destinations are checked for room/floor validity, bounds and conflicts. Restoring updates the existing core actor position.
