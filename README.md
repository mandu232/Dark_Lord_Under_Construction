# 마왕님은 공사중

던전을 짓다가 침입자가 오면 직접 칼을 들고 나서는 마왕의 이야기입니다.

**마왕님은 공사중**은 Unity로 만들고 있는 PC용 싱글플레이 2D 탑다운 액션·던전 방어 게임입니다. 방과 복도를 늘리고, 하수인을 배치하고, 마왕을 직접 움직여 적을 막습니다. 전투가 끝나면 시체를 회수해 병력을 보충하고 다음 침공을 준비합니다.

현재 플레이 목표는 **5웨이브 방어**입니다.

## 어떻게 플레이하나요?

새 게임은 도입 스토리와 튜토리얼로 시작합니다. 튜토리얼에서는 시체를 옮겨 하수인을 소환하고, 복도를 만든 뒤 적이 들어오는 **균열**을 옮기는 과정을 익힙니다. 새 게임 설정의 스토리 건너뛰기는 도입 스토리 씬을 생략하는 옵션이며, 인게임 튜토리얼은 진행됩니다.

준비할 때는 **B로 건설창**을 열어 방·복도, 시설, 함정을 배치합니다. 복도는 기존 던전에 연결해야 하고, 방은 복도에 붙여야 합니다. 방·시설·함정은 보유한 아이템을 사용하므로 웨이브 보상을 고를 때 다음에 무엇을 지을지도 생각해야 합니다. 하수인은 길게 눌러 원하는 방으로 옮길 수 있지만, 방마다 수용 인원이 정해져 있습니다.

적이 들어오면 하수인들이 싸우고 마왕도 직접 전투에 참여합니다. 기본 공격과 회피, 혈파와 혈막을 사용할 수 있으며, 코어에서 기술을 연구하면 Q와 R에 다른 스킬을 장착할 수 있습니다. **마왕과 코어는 체력을 공유합니다.** 마왕이 살아남는 것만큼 코어를 지키는 것도 중요합니다.

쓰러진 적 옆에서 **F**를 누르면 시체를 끌고 다닐 수 있습니다. 시체를 권속 소환소 가까이 가져가면 자동으로 흡수되어 소환 스택이 쌓입니다. 이후 소환소 옆에서 F를 눌러 **스택 1개로 하수인 1마리**를 소환합니다. 튜토리얼의 첫 소환은 혈 슬라임으로 고정되고, 이후에는 근접·원거리·지원 역할의 하수인 중 무작위로 나옵니다.

금화·혈액·혈석은 시설과 성장에 사용합니다. 하수인이 많아지면 매 웨이브 납부하는 혈액 유지비도 늘어나므로 병력과 자원을 함께 관리해야 합니다.

### 난이도와 침공

| 난이도 | 침공 방식 |
| --- | --- |
| 쉬움 | 준비를 마친 뒤 웨이브 시작 버튼으로 직접 시작 |
| 보통 · 어려움 · 악몽 | 카운트다운이 끝나면 자동으로 시작 |

자동 침공에서는 이전 웨이브의 적을 다 처리하지 못해도 다음 적이 들어올 수 있습니다. 침입 중에는 건설, 신규 소환, 하수인 재배치가 막힙니다. 보통 이상에서는 남은 시간을 보면서 준비하세요.

자동 침공의 준비 단계에서 배치 가능한 아이템과 진행 중인 공사가 없고 상호작용도 끝나면, 잠시 후 대기 시간이 빠르게 줄어듭니다. 마지막 10초는 원래 속도로 흐릅니다.

## 조작

키보드와 마우스를 기준으로 합니다.

| 입력 | 동작 |
| --- | --- |
| WASD | 이동 |
| 마우스 | 공격 방향 지정 |
| 좌클릭 / 누르고 있기 | 기본 공격 / 반복 공격 |
| Q | 공격 스킬 — 기본은 혈파 |
| R | 지원 스킬 — 기본은 혈막 |
| Space | 이동 방향으로 회피. 멈춰 있으면 바라보는 방향으로 회피 |
| F | 시체 들기·내려놓기, 소환소·코어 등과 상호작용 |
| B | 건설창 열기·닫기 |
| 하수인 길게 좌클릭 후 드래그 | 다른 위치로 재배치. 원하는 곳에서 버튼을 놓아 확정 |
| 우클릭 | 건설 배치 취소, 하수인 재배치 취소 |
| Esc | 열린 창이나 배치 모드 닫기. 시체 운반 중에는 내려놓기. 일반 플레이 중에는 일시정지 |

## 프로젝트 실행

**Unity 6000.6.2f1**을 사용합니다.

1. Unity Hub에서 해당 에디터 버전을 설치합니다.
2. 이 저장소를 내려받고, `Assets`, `Packages`, `ProjectSettings`가 있는 폴더를 Hub에 추가합니다.
3. 프로젝트를 열어 패키지 복원과 에셋 임포트가 끝날 때까지 기다립니다.
4. `Assets/Scenes/MainMenu.unity`를 열고 Play를 누릅니다.
5. 새 게임에서 저장 슬롯과 이름, 난이도를 정하고 시작합니다.

처음 플레이할 때는 `MainMenu`부터 시작하세요. `InGame` 씬만 바로 실행하면 타이틀의 새 게임 설정과 도입 흐름을 거치지 않습니다.

빌드에 등록된 씬은 `MainMenu → Story → InGame` 순서입니다. 이어하기와 스토리 건너뛰기는 `InGame`으로 바로 이동합니다.

## 개발 환경과 폴더

C#으로 작성했으며 URP의 2D Renderer, Input System, uGUI와 TextMeshPro를 사용합니다.

| 항목 | 버전 |
| --- | --- |
| Unity Editor | 6000.6.2f1 |
| Universal Render Pipeline | 17.6.0 |
| Input System | 1.20.0 |
| Unity Test Framework | 1.8.0 |

에디터 버전은 `ProjectSettings/ProjectVersion.txt`, 패키지 목록은 `Packages/manifest.json`에서 확인할 수 있습니다.

```text
Assets/
├── Scripts/
│   ├── Actors/        # 체력, 상태 효과, 캐릭터 공통 처리
│   ├── Dungeon/       # 던전 공간, 건설, 시설과 함정
│   ├── Gameplay/      # 웨이브, 튜토리얼, 전투 효과
│   ├── Minions/       # 하수인과 침입자 행동
│   ├── Persistence/   # 저장과 불러오기
│   ├── Player/        # 이동, 전투, 소환, 경제와 기술 연구
│   └── UI/            # 메뉴, HUD, 상호작용 창
├── Scenes/            # MainMenu, Story, InGame
├── Data/              # 건설 항목 등 게임 데이터
├── Prefabs/           # 캐릭터, 시설, UI
├── Editor/            # 에디터 도구
├── Settings/          # 렌더링과 입력 설정
└── Tests/PlayMode/    # 게임 시스템 테스트
Docs/                  # 설계, 구현 기록, 플레이 테스트 문서
ArtSources/            # 아트 원본과 제작 기록
Tools/                 # 제작·점검용 스크립트
Packages/              # 패키지 목록과 버전 잠금
ProjectSettings/       # Unity 프로젝트 설정
```

런타임 어셈블리는 `DarkLord.Runtime`, 테스트 어셈블리는 `DarkLord.PlayModeTests`입니다. 에셋을 옮기거나 추가할 때는 `.meta` 파일도 함께 관리합니다. `Library`, `Temp`, `Logs`는 Unity가 생성하는 폴더로 Git에서 제외되어 있습니다.

## 저장과 이어하기

저장 슬롯은 3개입니다. 저장 파일은 프로젝트 폴더가 아닌 `Application.persistentDataPath` 아래의 `Saves` 폴더에 `slot1.json`부터 `slot3.json`까지 생성됩니다. 저장본을 읽을 수 없으면 `.bak` 백업에서 복구를 시도합니다.

## 테스트와 빌드

**Window → General → Test Runner**의 **PlayMode** 탭에서 테스트를 실행합니다. 전투, 건설, 웨이브, 튜토리얼, 경제, 저장·불러오기 테스트는 `Assets/Tests/PlayMode`에 모아두었습니다.

PC 빌드는 **File → Build Profiles**에서 대상 플랫폼을 선택한 뒤 진행합니다. 필요한 빌드 모듈을 Unity Hub에서 설치하고, 씬 목록에 `MainMenu`, `Story`, `InGame`이 이 순서로 활성화되어 있는지 확인하세요.

기능별 검증 기록은 [Docs/AI](Docs/AI)에 있습니다. 각 기록은 작성 당시의 결과이므로, 빌드를 내보내기 전에는 현재 변경 사항에 맞는 테스트와 실제 플레이를 다시 확인해야 합니다.
